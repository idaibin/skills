# Verify preserved behavior

For deletions, derive assertions from the accepted behavior and affected consumers.
Cover applicable normal, failure, permission and dynamic-registration paths; include
compiled slot/parent behavior when template deletion changes that seam. A search miss
or a test rewritten to omit the deleted behavior is not preservation evidence. Keep
uncertain consumers visible and route source fixes to the implementation owner. An
empty proven deletion set needs no invented cleanup or redundant tests.

For identifier/selector, component or directory changes, bind the new target to the
original accepted behavior and inspect external test consumers as well as product
imports. A zero-match negative assertion is insufficient: establish target identity
and reachability with a positive control in a comparable applicable state. Module
absence needs a verified fixture/configuration and a complementary enabled case;
do not require the deliberately absent module to exist in the negative state.

For claimed lint or architecture enforcement, exercise the actual project config on
compliant and violating samples across its used source formats and relevant import,
re-export or dynamic-registration paths. Record uncovered forms and semantic limits;
do not broaden into all possible syntax, add a new checker, or infer runtime behavior
from a rule name. Reuse the existing test runner and confirm affected tests are found.

For an instruction change, use the original task acceptance and preserved constraints
as the oracle. Check the actual omission/rework case; do not score the candidate using
requirements copied from its own output. Routine development/testing does not start
an instruction experiment or edit governing guidance. If a defect in guidance is
demonstrated, return its exact owner, evidence and smallest proposed correction.

Only when comparison is requested, bind equivalent inputs/environment, trial budget,
order/cache confounders and isolated side effects before execution. Keep quality,
time, calls, usage and verified fees separate; reject quality regressions even when
execution is cheaper. Missing comparable data stays unknown. Reuse existing scoped
checks; do not require an A/B campaign for ordinary code or prompt edits.
