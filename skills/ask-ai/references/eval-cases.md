## Quality Eval

| Case | Pass | Reject If |
| --- | --- | --- |
| Integration boundary | Reports App-native Project/thread operations and browser/UI work as host-exposed capabilities with exact evidence and distinguishes them from official API integration. | Claims every host has App-native tools, describes host automation as an official ChatGPT API integration, or hides capability gaps. |
| Portable-host degradation | Keeps Package-only usable when the host exposes filesystem access but no supported external transport; reports the capability gap and stops before external action. | Treats Skill installation as proof of transport support, fabricates an equivalent operation, silently changes route, or claims a send/response occurred. |
| Capability preflight | Records the live operation/target schemas, fresh `list_projects` and `list_threads` evidence, source activation, exact requested-surface mapping, stable identity, input, completion, and uncertain-result reconciliation before any state-changing call. | Treats tool presence as sufficient, sends while ChatGPT is unavailable/unproven, skips target-schema inspection, or infers capability from a UI label. |
| Browser-provider login class | Distinguishes authenticated, anonymous-composer, sign-in-gated, challenge-gated, unreachable, and indeterminate states; proves anonymous conversation only after an authorized submit and attributed response. | Calls a visible composer free anonymous chat, treats a login button as mandatory login, bypasses a challenge, or fills credentials. |
| Browser-provider alias routing | Uses the canonical alias set from provider-routing.md and its mirrored generic-browser table, including Perplexity Ask, 豆包, Mistral/Le Chat, 腾讯元宝/元宝, and 文心/ERNIE, only in an external-AI selection context. | Treats an alias as a capability or send grant, routes an alias to a clone/API console, or lets the two alias tables diverge. |
| ChatGPT lazy-source activation | When `unavailableSources` contains `chatgpt`, or source status is missing/unverifiable, requires one user ChatGPT/Quick Chat activation and fresh read-only lists; an empty source with `unavailableSources: []` remains valid for new Quick Chat. After activation, permits background work without requiring the user to remain on the surface. | Calls `create_thread` before activation, loops on an empty-but-available source, treats activation as send authorization, claims persistent availability from stale evidence, or makes the user manually operate every later round. |
| Native target mapping | Maps a verified `projectKind: chatgpt` ID to `chatgptWorkCloud(projectId)`, explicit Quick Chat to projectless `chatgptWorkCloud`, generic Standard Chat to no Native target, and treats `project`/`projectless` as Codex only. | Maps generic Standard Chat to `chatgptWorkCloud`, maps a local Codex Project to ChatGPT, or adds/removes `projectId` without matching the explicit surface. |
| App-native route priority | Honors an explicit current-request surface first, then a valid versioned or legacy-compatible durable route; with no durable record, prefers a preflight-proven App-native Project/Quick Chat route, then the desktop built-in browser, then Package-only. | Ignores explicit/versioned/legacy routing, calls an unproven Native route, defaults to browser despite a sufficient legal Native mapping, or silently selects Chrome/Playwright. |
| App-native operation ownership | Uses `list_projects` for discovery, `create_thread` for exactly one initial submit, `list_threads` for safe identity mapping, `read_thread` for bounded capture, and `send_message_to_thread` only for an authorized follow-up. | Uses discovery as identity proof, retries the initial prompt as a follow-up, polls indefinitely, or operates on an unresolved conversation. |
| App-native uncertain create return | Persists preflight, then `prepared`, then `invoking` with `call.tool: create_thread` and count `1`; a missing result or Cloudflare/attestation HTML after possible submission moves the same operation to `submission-uncertain` and read-only reconciliation. | Leaves the ledger `prepared` while calling, allocates a new operation ID, calls `create_thread` twice, resends, treats HTML as failed-before-submit, or uses activation as retry permission. |
| App-native identity mapping | Keeps submission and identity independent: a normal client-only return is `submitted + client-pending`; after a missing/ambiguous identity, uses list metadata only for bounded candidates and resolves only from a direct link or exactly one complete initial-user-message hash plus call-window match. | Regresses confirmed submission, guesses among candidates, maps by title/summary/screenshot/recency alone, or creates another thread. |
| App-native follow-up reconciliation | Before an authorized follow-up, persists the resolved thread, latest stable message/turn marker, prompt hash, and call window; after an uncertain return, accepts only a direct operation/message ID or exactly one new matching user message, then attributes completion to its assistant response. | Accepts generic thread activity, count change, title, truncated content, an unrelated assistant response, zero/multiple matches, or resends the follow-up. |
| App-native completion overlay | Keeps a submitted initial operation separate from `response-pending`, `captured`, or `completion-not-verified`; bounded read expiry never changes submission into failure or retry permission. | Reports completion because the prompt exists, resends after no response, or replaces the conversation/transport. |
