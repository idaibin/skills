# Eval Cases

For a page-local copy change that preserves shared semantics, update only its applicable
Feature Spec. Preserve unchanged shared-authority bytes and approval. If shared content
changes, preserve the project's existing acceptance requirements, including exact-content
human approval when its adopted policy or accepted consumer requires it.

## Trigger Eval

| Prompt | Expected |
| --- | --- |
| `Build an implementation-ready contract for this selected mockup of the settings dialog.` | Trigger `ui-spec` Feature Spec. Record selected source and required states, responsive/accessibility rules, and per-slice readiness without generating images. |
| `Before ChatGPT Images explores this unapproved dashboard direction, verify the real source scope and Ant Design mappings, then keep one candidate UI spec and one complete prompt under ignored .codex/reviews/.` | Trigger `ui-spec` candidate direction. Verify source/product truth and ignore status, update spec before prompt, hash both, keep `DESIGN.md` unchanged, and hand named external transport to `ask-ai`. |
| `Our accepted shared Button and spacing conventions changed across dashboard and settings; update the shared contract.` | Trigger `ui-spec` Design System Spec. Resolve the existing shared contract and component/token owners, update the owned guidance, and apply its actual checks without forcing Google format adoption. |
| `Build a contract for this selected page in a new repo with no DESIGN.md yet, and establish its shared visual system.` | Trigger `ui-spec`, resolve accepted decisions and the smallest project-native authority, and use Google format only if explicitly adopted. Establish required shared decisions before dependent slice readiness. |
| `The accepted current page only needs accessible names on existing logo links; preserve every shared visual rule, and this project has not adopted DESIGN.md.` | Trigger a local Feature Spec, record `DESIGN.md: Not adopted (not required for this slice)`, and proceed from the accepted surface plus live source owners without creating shared visual authority. |
| `Create a contract for one flow but do not copy tokens/component semantics from the shared source.` | Trigger `ui-spec` Feature Spec. Reference the project-declared shared authority and reuse owner mapping instead of duplicating shared values in the slice artifact. |
| `Specify this settings page using its selected source; keep shared colors, spacing scale, global typography, radius, and Button semantics in DESIGN.md.` | Trigger `ui-spec` Feature Spec with page-level layout/state/interaction/component mapping only. |
| `This Git repository contains a shared frontend aggregate with two separately built apps; keep one accepted DESIGN.md at that aggregate.` | Resolve the aggregate as `<design-root>` from guidance and consumers; do not force the Git root or duplicate one file per app. |
| `Clean the final UI docs and move all old candidate evidence JSON out of formal docs.` | Keep the current UI contract durable and route historical evidence to verified ignored `.codex/artifacts/`. |
| `Specify this existing settings surface: preserve its brand and routes, keep one primary accent role, add dark mode only if the accepted contract requires it, and map shell/container/component padding without doubling the left or top inset.` | Trigger `ui-spec`; load visual-direction and layout governance, record Preserve mode, conditional dark-mode scope, semantic color exceptions, and the effective inset owner chain. |
| `Our explicitly adopted Google-format DESIGN.md has an unknown heading; no additional completeness policy applies.` | Keep the unknown heading preserved, report it in the notes, and do not impose the strict eight-section policy. |
| `A duplicate section appears in our adopted Google-format DESIGN.md while updating shared semantics.` | Use official diff/lint flow and treat duplicate section as an immediate error condition until resolved by source owner. |
| `Run lint before exporting our adopted Google-format design output.` | Run lint first, require success without error, and treat export as explicit derived output only after shared authority is accepted. |
| `Specify this approved dialog so long localized content, intermediate widths, its critical action, inner scroll, and overlay behavior remain usable.` | Trigger `ui-spec` Feature Spec and add only the applicable task-completion geometry and acceptance rules. |
| `Admin only needs 1920x1080 verified; 1440x900 is useful if time permits, and mobile is outside this request.` | Trigger `ui-spec` Feature Spec with an Admin-local viewport matrix: `1920x1080` required, `1440x900` optional, mobile excluded with the user's request as evidence. Hand the unchanged matrix to implementation, audit, and runtime verification; do not make this a global default. |
| `The current runtime geometry differs from exact values in the approved source inspect panel.` | Keep source target and browser-computed runtime in separate delta columns; use inspect-panel values as `source-extracted` and do not call current geometry already aligned. |
| `Lanhu shows the same card gap as 16px three times and 17px once; use the default even-grid policy.` | Preserve all four source-extracted values, cluster only the same semantic gap, and target 16px with the recorded user policy; do not rewrite the 17px observation. |
| `Specify the catalog page with SearchBar, CatalogCard, DownloadDialog, and shared states; the project has component guidance and a concise project map.` | Keep page composition, page states, and interaction in the UI slice; use the guidance and project map to reach source owners, leave props/slots/events and tokens in their owners, and require live-source revalidation before implementation. |
| `Specify a page in a project whose adoption record declares components/ui, a Registry, and generated tokens.` | Keep page composition and states in the Feature Spec, shared semantics in the declared visual authority, component APIs in source/types, and Registry/token lifecycle in their declared owners; a component adoption record alone does not require Google format. |
| `Specify the dashboard UI from this accepted project screenshot.` | Trigger `ui-spec` with the screenshot as the selected visual source; a versioned project-owned screenshot referenced in the README is an accepted current UI surface. |
| `Turn this accepted admin shell into a fixed UI contract and require all navigation and action icons as SVG.` | Trigger `ui-spec`; keep shared token/icon-family rules in their project-declared authority and page-local composition in the Feature Spec, resolve the real icon owner and rights, and specify SVG role/render/state/accessibility/fallback acceptance without writing SVG source. |
| `Freeze this accepted interaction so implementation and later comparison use the same conditions, without turning its measurements into global defaults.` | Trigger `ui-spec`; record a task-local comparison-basis revision with surface/entrypoint, viewport/environment, content/data shape, locale/theme/zoom, start state, input, expected end state, relevant owners, and intentionally variable dimensions. |
| `Prepare an unapproved candidate direction for image exploration.` | Bind the handoff to the candidate spec/prompt revision and hashes. Do not require an accepted comparison-basis approval or treat candidate measurements as accepted targets. |

## Non-Trigger Eval

| Prompt | Expected |
| --- | --- |
| `Generate three visual alternatives for this dashboard and let me pick.` | Route to host Product Design; do not start `ui-spec` without selected source. |
| `Implement this slice in code now.` | Route to `dev-frontend`; consume implementation-ready `ui-spec` artifact. |
| `Critique this interface and redesign it.` | Route to Product Design or audit owner; do not do redesign in `ui-spec`. |
| `Collect runtime screenshots and network logs for the accepted surface.` | Route to `ops-browser` or `ops-client`; do not claim runtime evidence in `ui-spec`. |
| `DESIGN.md and the matching UI slice already exist; identify their file types before implementation.` | Let the consumer classify and read them directly; do not trigger `ui-spec` merely for recognition. |
| `No visual source or accepted UI surface is available; specify the UI anyway.` | For implicit routing, do not trigger `ui-spec`; route to `product-spec` for unresolved behavior or host Product Design for visual exploration. If `ui-spec` is explicitly invoked, stop as `evidence-incomplete`. Do not fabricate a visual source. |
| `Send this prompt to ChatGPT Images and keep correcting it in the chat until it looks right.` | Route external transport to `ask-ai`; require local candidate-spec-first and complete-prompt synchronization before each authorized send. `ui-spec` never operates the provider. |
| `Replace these icon files with new SVG path data in the frontend now.` | Route source edits to `dev-frontend`; `ui-spec` may supply an accepted icon contract but does not author SVG code. |

## Scenario Eval

| Scenario | Correct decision | Reject if |
| --- | --- | --- |
| Several routes show the same Drawer, motion and inset discrepancy | Freeze one comparison basis and resolve shared shell/overlay/component owners before per-route specs; keep only proven exceptions local. | Repeats shared rules as page overrides or marks a conflicted slice Ready. |
| Product retains submitted input after rejection and the accepted source includes a dialog with error feedback | Specify retained-value visibility, feedback/overlay/scroll ownership, focus, and reachable recovery at the accepted viewport; distinguish specification from runtime evidence. | Treats state-variable retention as visible proof, lets feedback hide the fields, or invents Product retry semantics. |
| Product clears a sensitive field after failure, or has not decided whether an uncertain submission can be retried | Honor the accepted clearing rule; keep only a transition dependent on unresolved Product semantics not Ready. | Forces universal retention, enables an unapproved retry, or blocks unrelated confirmed UI states. |
| The supplied accepted UI contract already covers every requested failure-state assertion, but no implementation or browser evidence is supplied | Return no change for that contract; keep file readback and runtime validation separate and unverified. | Claims supplied clauses are missing, invents a contract update, or treats preview/runtime absence alone as a UI readiness blocker. |
| An accepted shared color-role change belongs to theme.css and component guidance; the project has no DESIGN.md | Update only the owned shared guidance and map its existing token/component owners; use project-native checks and leave source implementation to dev-frontend. | Creates Google-format DESIGN.md, requires a generator or independent approver, or copies live values into a parallel authority. |
| A project's existing DESIGN.md is plain Markdown and has no declared Google-format or completeness adoption | Preserve that actual accepted contract and its checks; filename alone activates neither profile. | Runs Google lint merely because of the filename or infers strict policy adoption from file presence. |
| A project explicitly adopts Google format, omits irrelevant sections and retains a custom section, but does not adopt ui-spec-design-completeness/1 | Apply official format lint/diff and the project's acceptance; record the additional policy Not applicable and retain supported content. | Requires the eight-section template, extra token groups or independent JSON approval. |
| The project explicitly adopts ui-spec-design-completeness/1 and the candidate is incomplete or adopted approval binds stale bytes | Preserve strict section/source/independent-approval checks; return the actual not-ready or awaiting-trusted-approval-verification state and block dependent readiness. | Disables the policy under the new default, downgrades required evidence to optional, or claims a local record proves trusted approval. |
| New repo has no resolved design authority, one selected slice exists, and first adoption of a shared visual system is explicitly required | Establish the smallest project-native contract from accepted decisions, identify actual token/component owners and apply the chosen format and project acceptance rules. | Invents token values, assumes Git root, mandates Google format or independent approval without adoption, or fabricates a diff baseline. |
| Unapproved image exploration uses a real current product surface | Inspect product/source scope and live component/library owners; write the ignored candidate spec first, rewrite a complete prompt, verify paths/ignore status/hashes, then hand the frozen pair to the visual owner or `ask-ai`. Keep formal `DESIGN.md` unchanged and report `Not Ready`. | Invents concept-only features, writes the candidate into formal docs, sends a delta or chat-only correction, skips hashes, or calls generated output accepted/implemented. |
| A candidate default page depicts an open Drawer | Define the default with the Drawer closed and absent from layout; specify its open interaction state separately with trigger, focus, close, and overlay behavior unless an accepted product contract explicitly makes it default. | Reserves permanent default-state space for the Drawer or treats one screenshot as both default and interaction acceptance. |
| Existing accepted surface has no adopted DESIGN.md and the slice preserves all shared visual semantics | Keep the Feature Spec local, record the non-adoption disposition, use repository-native visual owners as current implementation facts, and mark DESIGN lint/diff `Not applicable`. | Forces DESIGN.md adoption, invents a shared token authority, or treats current adapter values as a new semantic contract. |
| Feature Spec only reuses accepted shared visuals | Reference the actual accepted shared authority and avoid copying token/component values into slice file. | Copies shared token map or component semantics into the slice. |
| Page contract maps a selected source | Keeps page layout, states, interaction, responsive/accessibility behavior, and component mapping in the Feature Spec while linking shared decisions and live values to their declared owners. | Turns the Feature Spec into a parallel design-system document or omits page-level implementation mapping. |
| Page contract uses component guidance and a project map | Names human-readable component roles, reads only relevant guidance/map entries, and verifies paths, registration, states, and interfaces in source. | Creates a component-ID registry for AI, copies props/slots/events or token values into the page spec, omits component composition, or treats a map row as live-source proof. |
| The project has a maintained page projection with human Markdown sources. | Preserve Product, page UI, and component Markdown as separate authorities; consume the projection only for its named non-LLM purpose and verify source reachability and drift lifecycle. | Requires a projection for ordinary UI work, lets it replace Markdown acceptance or cross-page guidance, or duplicates tokens/API/DTO/props/slots/paths. |
| A UI Markdown authority or local reference uses an absolute local path or escapes its declared owner/workspace root. | Reject the reference as non-portable before following it; require an owner-relative path whose resolved target remains inside the boundary. | Accepts the path because it exists on the current machine or because its lexical form is relative. |
| A relative UI Markdown authority or local reference is a symbolic link whose final target leaves the declared owner/workspace root. | Resolve the final target and reject the reference before consuming it, without introducing a schema requirement. | Checks only lexical containment. |
| Two UI contract decisions remain and the second depends on the first; the current host mode exposes native structured choice | Ask only the prerequisite decision through the native control, put the recommended visible outcome first, record its exact UI-contract mapping, and recompute the frontier. If the host reports that the control is unavailable in the current mode, say exactly that and use concise numbered options. | Asks dependent choices together, uses prose despite an available native control, claims the whole client is unsupported, claims the Skill added the control, or crosses into Product behavior. |
| Shared visual semantics change for multiple domains | Update the existing shared authority, run its applicable checks, and report affected consumers and regression status before dependent readiness. | Treats change as local styling only, duplicates shared rules, or forces a new format. |
| Valid evidence JSON exists under formal docs but has no durable team consumer | Move it to verified ignored `.codex/artifacts/`; keep current acceptance in the UI Spec. | Treats schema validity as publication authority or leaves candidate/final history in the index. |
| UI Spec ID or DESIGN version is an edit date | Remove the date-based revision unless the project has a semantic version policy; preserve business-effective dates only when they affect acceptance. | Uses the newest date as an authority rule or deletes a date that changes behavior. |
| Google-format DESIGN.md has an unknown heading and no stricter policy applies | Preserve the unknown section and continue with known ordered content. | Removes it silently or applies eight-section completeness without adoption. |
| Google-format DESIGN.md has duplicate section heading | Reject with hard blocker until resolved. | Continues and marks Ready. |
| Required Google-format lint or diff cannot run due to a missing parser or authorization | Mark checks as `Not verified` and keep only dependent readiness blocked. | Claims success without evidence, invents a network requirement for a local parser, or issues dependent `Ready`. |
| A desktop-only Admin acceptance request names one mandatory and one budgeted viewport | Matrix records viewport size/orientation, environment, state/fixture, assertions, and evidence source. `1920x1080` is required, `1440x900` is optional, and mobile is excluded only from this slice's acceptance scope. | Treats a skipped optional check as a failure, treats excluded mobile as an unsupported-device claim, or applies Admin sizes to unrelated surfaces. |
| Design tool cannot select an icon, but the screenshot can be viewed at 200% | Use the zoomed image only for `visually-inferred` comparison; keep exact icon size `proposed` or `Not verified`. | Copies the current runtime icon size or a pixel estimate into the target as verified. |
| Repeated Lanhu spacing differs by one pixel | Apply the even-grid rule only when at least three same-semantic samples have a strict even majority and every outlier is within 1px; keep raw evidence and approval separate from the target. | Pools unrelated gaps, rounds an odd majority arbitrarily, or applies the rule to widths, type, borders, radii, icons, or assets. |
| Every product currently uses one generic gradient icon | Specify real per-item asset ownership and only an isolated failed-item fallback. | Treats the current fallback as a normal visual asset strategy. |
| A selected page uses a branded, parameterized gradient behind readable content | Bind source rights, recipe, text-safe area, reduced-motion state, export identity and target-surface evidence; hand rendering to `dev-frontend`. | Copies an unlicensed source, infers contrast from a palette name, or treats an export as runtime proof. |
| Accepted page requires a fixed shell and SVG icon family | Keep shared token/icon-family semantics in the declared shared authority; keep header/navigation/content/overlay ownership, page states, and role-to-icon placement in the Feature Spec. Resolve existing library/wrapper, rights, canonical geometry, render sizes, family weight, accepted coloring strategy, accessibility, and isolated fallback or evidenced `None`; require a focused icon gallery and same-state runtime verification. | Copies shared values into the page spec, hard-codes attachment examples as universal values, creates SVG path data, introduces a parallel icon library, or calls source/gallery review runtime proof. |
| An accepted downstream consumer requires ui-spec-design-completeness/1 for its DESIGN package | Hand off the exact immutable basis and package-relative DESIGN.md, completeness result, selected source, and approval evidence with closed hashes/byte lengths; keep producer state distinct from independently trusted acceptance evidence. | Marks the required policy Not applicable, accepts a local record alone, mutates producer state to simulate trusted acceptance, or accepts stale/different bytes or principal identity. |
| An acceptance-decisive interaction condition changes after implementation or comparison evidence exists | Advance the task-local comparison-basis revision, identify affected implementation/evidence/handoffs as stale, and require reconciliation on the new basis before readiness. | Silently edits the contract, reuses old evidence, or treats an in-flight result for the old conditions as current. |

## Quality Eval

| Case | Pass evidence | Reject if |
| --- | --- | --- |
| Source gate | selected/accepted source recorded with identity, revision, approval, rights, `use`, `ignore` | starts without source identity or selected-source approval |
| Product truth | product goals, actions, states, and failures grounded and separated from design | invents product logic from mockup appearance |
| Design authority | records actual shared owner and separately resolves project-native, explicit Google-format and additional completeness requirements; keeps token values and component APIs in their declared sources | treats a shared change or DESIGN filename as adoption, discards an existing required policy, assumes Git root, duplicates per app, or introduces another authority |
| Evidence placement | task evidence defaults to verified ignored `.codex/artifacts/`; durable publication passes the consumer/lifecycle gate | commits evidence under formal docs merely because it validates |
| Candidate lifecycle | candidate spec is the local source; prompt is complete and synchronized; both ignored paths and hashes are verified before one downstream send; approval gates formal promotion | external chat owns corrections, only a delta prompt is retained, formal DESIGN.md changes early, or external output is treated as acceptance/runtime proof |
| Visual direction | Records a compact Design Read and only applicable dials; keeps one primary accent semantic role with state-color exceptions, makes dark mode conditional, and classifies Preserve versus Overhaul before changing an existing surface. | Installs `8/6/4` as a default, flattens semantic colors, mandates dark mode, or silently overhauls the existing brand/IA. |
| Nested inset ownership | Specifies shell, content-container, page, panel/component, and control ownership; records effective left/top/right/bottom inset and any flush-scrollbar exception without prescribing incidental DOM. | Adds the same page padding at parent and reusable component, ignores top/left alignment, or moves scrollbar inset to the wrong owner. |
| Evidence precision | marks `source-extracted`/`browser-computed`/`visually-inferred`/`proposed`/`Not verified` and includes applicable validation outcomes | treats unknown values as verified facts or reports an inapplicable policy as passed |
| UI decision frontier | Resolves facts first, asks one prerequisite-complete material UI decision at a time, uses available native structured choice for bounded mutually exclusive outcomes, otherwise names the actual mode limitation and falls back concisely, then records the selected outcome and contract mapping. | Re-asks settled choices, batches dependent questions, ignores an available native control, overstates a mode limitation, or treats a selection as implementation/delivery authority. |
| Delta traceability | keeps source target, current runtime, and accepted contract separate with evidence IDs and uses design inspect values before screenshot estimates | promotes runtime computed values into source targets or summarizes them as safe-to-preserve design values |
| Reproducible comparison basis | records a task-local revision, surface/entrypoint, viewport/environment, data/content shape, locale/theme/zoom, start state, trigger, expected end state, relevant owners, and intentional variables; invalidates stale evidence when a decisive field changes | compares different states or environments, omits a decisive input, installs observed values as universal defaults, or reuses old-revision evidence |
| Measurement normalization | Retains every raw source value and evidence ID, records cluster semantics and policy authority, and normalizes `[16,16,16,17]` to a 16px target only under the bounded even-grid rule. | Erases the outlier, treats screenshot pixels as exact, mixes properties, or normalizes non-spacing measurements by default. |
| Design-system gate | shared changes use their actual owner/checks; explicit Google format requires pinned format lint/diff, while explicit or consumer-required ui-spec-design-completeness/1 retains every strict lifecycle gate | conflates format with completeness, applies strict policy without adoption, or skips an existing required gate |
| Adopted component/token boundary | References the adoption record and human component contract for ownership, leaves props and token values in source owners, and records project-native validation/runtime evidence separately. | Creates a second Registry for AI, copies generated tokens into the page spec, or lets static gates prove rendered behavior. |
| Explicit strict policy: format-valid prose-only false positive | official lint may report zero for prose-only frontmatter and unknown H2; required completeness must still return `not-ready` | treats format validity as strict-policy completion or applies this policy to a format-only project |
| Explicit strict policy: first-adoption completeness | canonical eight H2 sections stay in order; colors/typography/spacing/rounded and applicable components use machine tokens or concrete official omissions; prose names token application semantics and source hash closes | accepts aliases/unknown H2 as replacements, empty omission reasons, token dumps, or current CSS as self-approving target |
| Accessibility and responsive contract | defines focus, overflow, reduced-motion, localization, and acceptance for each slice | skips accessibility/responsive rules in contracts |
| SVG icon contract | when applicable, records semantic roles, actual owner/library and rights, approved family/geometry/render/state and coloring rules, accessibility, safety, accepted isolated fallback or evidenced `None`, and focused plus same-state acceptance | forces `currentColor` over an accepted brand/token strategy, invents exact 24px/2px rules, embeds SVG paths/source imports, silently substitutes a generic icon, or omits runtime acceptance |
| Viewport acceptance scope | every applicable slice has required/optional/excluded entries with size, environment, state, assertions, and evidence source; current user requirements override older specs | calls one screenshot full coverage, omits the evidence source or state, or treats an excluded viewport as unsupported |
| Multi-surface gating | per-slice readiness plus shared index and explicit partial/complete status | uses one omnibus contract or one package-wide readiness only |
| Independent readiness axes | reports UI visual/interaction readiness only and requires a separate Product verdict when Product behavior applies | treats UI `Ready` as Product approval or lets either owner overwrite the other |
| Handoff | per-slice artifact and readiness delivered to dev-frontend with closest accepted page when one exists, actual public component/style owner, any justified exception and remaining gaps | omits per-slice readiness, names no actual reuse owner, invents a reference, or leaves blockers unresolved |
| End-of-work checklist | reports each readiness item by name (source, shared owner/profile, applicable DESIGN format/completeness, deltas, viewport, asset/icon owner, states and evidence); evaluates in numeric order; reports unused profiles Not applicable, first failed required item Not Ready, and mixed ready/blocked slices Partial | skips a required item, invents a profile requirement, downgrades a blocking unknown to Partial, or marks a required gap Ready |

## Scoring

For a failed submission, UI keeps Product-approved retained input visible through
feedback, focus and recovery; an unknown outcome does not let UI choose retry policy.
An already accepted UI clause can return no-change without browser proof, while its
runtime claim remains separate and unverified.

Score each quality case 0–10. Minimum pass:

- routing is correct
- every quality case score >= 8
- no hard blocker remains
- applicable project, Google-format and additional policy gates pass before dependent `Ready`; unused profiles are `Not applicable`, while unavailable required gates remain explicit blockers and `Not verified`

| --- | --- | --- |
| Interactive state distinctions | Keeps applicable transient/persistent/disabled/pending combinations and focus/retry policy in existing UI contract. | Invents universal colors, dimensions or a parallel schema. |
