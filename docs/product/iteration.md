# Skills 产品与迭代 PRD

## 产品定位与用户

Skills 提供可独立安装、运行时自包含的工程能力包。产品价值是让使用者选择最近的责任能力，在明确权限、范围和证据边界内得到可用结果。当前 catalog 由根 `skills-index.json` 持有；安装入口为 `INSTALL.md`；包行为由各自 `SKILL.md` 及直接引用持有；[skill standard](../skills/skill-standard.md) 与 [routing standard](../standards/skill-routing.md) 继续拥有维护规范。

| 用户 | 工作 | 预期结果 |
| --- | --- | --- |
| 开发者/普通 AI 使用者 | 找到并独立使用所需能力 | 正确触发、最小读取、结果可验收，不越权 |
| 宿主/编排 consumer | 解析 capability、输入输出、权限与失败 | 同版本合同匹配，缺能力/证据时明确停止 |
| 维护者 | 更新包、分发和验证 | 元数据/路由/文档同步，变更收益有实际证据 |
| 审查与接手者 | 复核结果，接续中断任务 | 能定位加载版本、原 basis、失败与恢复材料 |

## 当前能力范围

当前 19 包按工作职责覆盖回顾、仓库认知、领域/产品/API/UI 规格、任务化、前端/TypeScript/Java/Rust 实现、测试设计与验收、既有审计、变更审查、Git 交付、浏览器/客户端操作、外部 AI 协作和写作。精确包集与可变版本只读 catalog，本文不维护镜像清单。

各能力可独立使用；handoff 传递证据而不是权限。目标项目拥有业务合同和任务状态，catalog 不保存真实项目台账。`dev-tests` 继续遵循其 candidate 采用门，不能由静态检查自动晋级。

## 主流程与异常语义

使用者提出一个目标→宿主发现最近能力→核对输入、范围和权限→执行或交接→输出结果及分层证据。多个能力无法区分时明确选择依据；缺输入/权限/运行面时只暂停依赖层，留下可接续下一步。读取 Skill 不等于执行 Skill，静态 routing 通过不等于模型实际触发正确。

对修改/提交类任务，失败和未知完成结果必须按原能力及项目合同处理。有效 no-op 保留，不为了表现“做了工作”新增代码或检查；对原本安全停止的用例，不以强行执行取得高完成率。

## 质量与数据要求

公开 fixtures 必须合成且与真实项目无关；真实 trace、账号/宿主状态与业务结果保留项目或私有证据位置。质量文档只发布可复查的脱敏总结与限制。静态 token/context 估计不能充当完整真实用量。

通过标准以选择、过程、产物/效果、停止诚实性、效率五个维度分开报告。只有实际覆盖维度可通过；缺失 terminal/trace 不推定能力未使用、质量为零或整个 catalog 不可用。跨模型基准和安装更新是独立范围，不默认外发私有材料。

## 后续范围与成功信号

先维护现有能力边界和真实消费者，暂不为不确定需求增加公共包或第二目录。S-R01–04 解决可接手性与可信度，S-R05 再决定保留、简化或扩大投入。候选晋级需要其原生采用门和独立接受，不由本文件批准。
