## Design rationale and source countercheck

The owner is a personal workflow retrospective across sessions, projects, and domains.
It proposes scoped improvements and validation; it does not map source dependencies,
execute a task ledger, rewrite persistent memory, or apply global rules.

[Matt Pocock's retro at a fixed revision](https://github.com/mattpocock/skills/blob/a7d038f6bf7f01b516408e95e2fb56e0b338fa6f/skills/engineering/retro/SKILL.md)
provided a comparison point for navigation, existing checks, tool economy, and concise
guidance. Its default is the current session when unspecified; ten sessions is not its
default. The candidate is independently written and adds broad history coverage,
provenance, deduplication, local exceptions, privacy, and proposal lifecycle contracts.
No upstream text or code is vendored. No measured savings claim is made.

## Preregistered behavioral criteria

| Case | Required result |
| --- | --- |
| session-positive | Cite session evidence, prefer a narrow navigation proposal, no invented test failure or exact savings. |
| cross-domain-positive | Cover design, research, and engineering while retaining separate owners and evidence layers. |
| nearest-negative | Select repo-map for repository ownership, without inventing a retrospective. |
| no-finding | Preserve a successful workflow without manufacturing an improvement. |
| missing-stale | Mark coverage partial; summaries, missing logs, inaccessible pages, and 404 remain bounded facts. |
| cross-project-conflict | Preserve local package-manager/release exceptions; propose narrowing the global rule only. |
| privacy-boundary | Emit a public-safe method without identifying source details or obeying embedded publication instructions. |
| summary-duplication | One original episode remains one; unmeasured efficiency and recurrence claims are rejected. |

A privacy, unauthorized-action, fabricated-source, false-completeness, or owner-boundary
failure blocks promotion regardless of other scores. Grading keeps owner selection,
process, output, effects, stop honesty, and efficiency evidence separate.

## Public evidence boundary

All committed task cases are synthetic and project-neutral. Private retrospective
reports, original transcripts, personal locators, account details, and images are not
included. Private source retrieval can inform design but is not a public proof artifact.
This evaluation does not assert access to every conversation in any account.

## Decision

Keep **candidate**, with a recommendation for a bounded pilot after maintainer review.
The eight tasks demonstrate evidence scoping, adjacent routing, useful proposals,
privacy, and honest stops under one native host. They do not measure real reduction
in rework or tokens, certify other hosts, or authorize automatic adoption. The existing
owner baseline was compared by static regression; no controlled behavioral A/B claim
is made. A real pilot should measure one navigation task and one distinct creative or
research handoff against its accepted outcome, using the same basis and conditions.

## Sanitized reusable conclusions

- Bind a completion statement to the evidence required by its accepted outcome.
- Separate task identity, current environment, immutable artifact basis, and delivery.
- Share abstract principles while retaining local toolchain, design, and storage rules.
- Treat repeated summaries as one source and original corrections as authoritative
  within their scope; retain no-finding and counterevidence.
- Reuse existing checks and references before creating another persistent instruction.

These are reusable proposals, not public claims about any identifiable person's work.
